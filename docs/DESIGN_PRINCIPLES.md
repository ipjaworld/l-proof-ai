# L-Proof-AI Design Principles

이 문서는 랜딩의 비주얼 시스템(색·타이포·그래픽 모티프)과 그 뒤에 있는 판단 기준을
정리합니다. 카피/콘텐츠 톤은 `docs/POSITIONING.md`를 따로 봅니다. 디자인을 만지는
모든 작업(로컬, 다른 PC, Codex 포함)은 새 장치를 추가하기 전에 이 문서를 먼저
확인합니다.

## 이미 있는 그래픽 언어

L-Proof-AI는 "증명 문서" 콘셉트의 편집 디자인을 쓰고 있습니다. 아래 네 가지가
전체 페이지를 관통하는 유일한 장치이고, 이것만으로 통일감을 냅니다.

1. **검증 등급 라인** — 점선(미검증) / 파선(보도 기반) / 실선(공식 확인) / 실선+도장(직접 테스트).
   `proofLevels`에서 정의되고 `.proof-line-*` 클래스로 표현됩니다.
2. **L-Stamp** — 손도장처럼 살짝 기울어진 커스텀 SVG 마크. "직접 확인했다"는 인증의
   시각적 서명 역할.
3. **모노스페이스 eyebrow 라벨** — 각 섹션 상단의 대문자 라벨(`NIGHT / UNFILTERED`,
   `PROOF LEVEL`, `THE PERSON IN THE LOOP` 등). 신문/문서 상단 태그처럼 기능.
4. **페이퍼 카드** — 테두리 + 옅은 그림자로 "실물 문서"를 흉내 낸 카드(`brief-paper`,
   `signal-record`). 배경이 어두운 섹션 위에서는 밝은 카드로 대비를 만듭니다.

색 토큰: `--night`(어두운 남색), `--dawn`/`--morning`(밝은 배경), `--ink`(본문 텍스트),
`--muted`(보조 텍스트), `--line`(구분선), `--stamp`(포인트 레드). 폰트: 본문은
Pretendard, 인용구(Lee's Take, WhyL 블록쿼트)만 세리프(KoPub Batang 계열), 라벨은
모노스페이스.

## 협상 불가능한 원칙

**실제 자산(사진·일러스트·텍스처) 없이 코드만으로 영화적/분위기 있는 연출을 흉내 내지
않는다.** 위 네 가지 장치는 전부 코드만으로 완성도가 나오는 그래픽 언어입니다. 반면
"야간에서 새벽으로 서서히 밝아지는 스크롤 연출" 같은 건 실제로는 사진/그레인 텍스처
같은 자산이 받쳐줘야 설득력이 생기는데, `color-mix`나 `blur` 같은 CSS 트릭만으로
시도하면 흔한 SaaS 랜딩 이펙트처럼 보입니다. 이건 "사람이 직접 만들었다"는 이 프로덕트의
핵심 주장과 정반대 인상(=AI가 대충 만든 느낌)을 만들기 때문에 특히 조심합니다.

**Why:** 2026-09-14, `NoiseAtNight` 컴포넌트가 정확히 이 문제였습니다. 스크롤 진행률을
JS로 계산해 `color-mix`로 야간→새벽 색을 블렌딩하고, 좌표를 하드코딩한 카드를 흩뿌리는
구조였는데, 반복해서 보면 의도한 연출이 전혀 살지 않고 이 섹션만 톤이 붕 떠 있었습니다.
운영자가 직접 지적해서 걷어냈습니다 (client 컴포넌트 → 정적 서버 컴포넌트로 재작성,
JS 스크롤 리스너·color-mix·좌표 하드코딩 전부 제거, 위 4가지 기존 장치로 재구성).

**How to apply:** 새로운 시각 효과를 제안하기 전에 먼저 자문할 것 — "이걸 실제 자산
없이 코드만으로 만들면 그럴듯해 보이는가, 아니면 얕아 보이는가?" 얕아 보일 여지가
있다면, 새 장치를 만들지 말고 위 4가지 기존 언어(라인/스탬프/라벨/페이퍼 카드)를
재조합해서 표현한다. 자산이 실제로 준비된 뒤에만 사진/일러스트 기반 연출을 다시
고려한다.

## 반응형 원칙

- 두 컬럼 그리드(`why-section`, `person-section`, `noise-inner` 등)는 900px 이하에서
  1열로 접는다.
- 767px 이하에서는 큰 패딩을 줄이고(`padding-block: 6rem` 수준), 장식적 요소보다
  가독성을 우선한다.
- 스크롤에 의존하는 상태 변화(예: 이전 noise 섹션의 진행률 기반 색상 전환)는 만들지
  않는다 — reduced-motion 사용자, 저사양 기기, 그리고 무엇보다 위 원칙과 상충한다.
