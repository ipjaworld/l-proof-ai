# AI가 코드를 더 쓰자, Git부터 바빠졌다

코딩 에이전트가 여러 작업을 동시에 진행하자 OpenAI의 저장소에서는 브랜치와 푸시, 가져오기 요청이 늘었습니다. 한때 병합 성공률이 90% 아래로 떨어졌다고 합니다. 회사는 Git 사용법을 바꾸는 대신, 그 요청을 처리하는 서버를 새로 만들었습니다. 11월 2일 공개한 Pando 이야기입니다. [OpenAI의 설계 설명](https://openai.com/index/scaling-git-at-openai/)

14호에서는 10월 31일~11월 5일 오전에 확인한 소식 가운데 코드 저장·검토, 보안 검사, 에이전트 스킬 업데이트, 모델 가중치 공개를 골랐습니다. 자료 확인 마감은 11월 5일 08:24 KST입니다. 아래 사실은 모두 **03 · 공식 확인**입니다. 발표 주체의 글과 배포 자료를 확인했으며 제품 동작이나 성능은 직접 재현하지 않았습니다. 마지막 ‘L-Proof의 해석’은 이 자료를 바탕으로 한 별도의 판단입니다.

## OpenAI — Git 서버를 다시 만들고, 리뷰 도구 회사를 인수하기로 했다

Pando는 OpenAI 내부 개발에 쓰이는 Git 호환 저장소 서버입니다. 서로 다른 브랜치의 쓰기 작업을 독립적으로 처리하고, 여러 사용자가 같은 기록을 가져갈 때 전송 파일을 재사용합니다. OpenAI에 따르면 운영 환경에서 푸시 시간의 중앙값이 거의 5분의 1로 줄었습니다. 이 수치는 회사 내부 관찰이며 일반 Git 호스팅 서비스의 성능 약속은 아닙니다. 여러 브랜치를 한꺼번에 읽는 사람이 모든 브랜치의 동일한 시점 상태를 보장받지 못하는 설계상의 교환도 있습니다. Pando는 현재 OpenAI의 모노레포에 쓰이지만 외부에 제공하는 서비스로 발표된 것은 아닙니다. [Pando 기술 글](https://openai.com/index/scaling-git-at-openai/)

11월 4일에는 코드 저장 서비스와 오픈소스 개발 도구를 만드는 Pierre Computer Company를 인수할 계획이라고 발표했습니다. Pierre의 파일 탐색·차이 보기 라이브러리인 Trees와 Diffs는 이미 Codex 앱에 쓰이고 있습니다. Pando가 변경을 주고받는 속도를 다룬다면, Pierre의 도구는 사람이 변경을 읽고 고치는 화면에 닿아 있습니다. 다만 **인수는 아직 완료되지 않았고**, 규제 승인 등 종결 조건이 남아 있습니다. 향후 Codex에 어떤 기능이 추가될지도 확정된 출시 일정으로 발표되지는 않았습니다. [인수 발표](https://openai.com/index/openai-to-acquire-pierre/)

## Vercel — 푸시할 때마다 AI 보안 검토를 붙인다

11월 2일 공개 베타로 나온 Vercel Security Review는 팀이 기능을 켜면 연결된 GitHub 저장소의 푸시마다 변경 코드를 검사합니다. PR뿐 아니라 운영 브랜치에 직접 푸시한 변경도 대상입니다. 권한 확인 누락이나 비밀 값 노출 같은 문제를 찾고, 결과를 보안 대시보드에 보여줍니다. 비공개·내부 저장소에서는 GitHub 검사 결과와 PR 댓글도 남깁니다. 팀은 자연어로 보안 정책을 정할 수 있고, 수정이 필요하면 별도 허가를 거쳐 Vercel Agent가 고치게 할 수 있습니다. [Vercel 발표](https://vercel.com/blog/vercel-security-review)

검토 대상은 변경분과 주변 코드입니다. 따라서 보고된 문제를 고치는 과정과, 보고되지 않은 코드까지 안전하다고 결론 내리는 일은 구분해야 합니다. 기능은 Vercel Pro·Enterprise 팀에 공개 베타로 제공되며, 보안 검토는 11월 10일까지 무료입니다. 이후 이용 요금과 에이전트를 통한 수정 비용은 별도 조건을 확인해야 합니다. [이용 범위와 요금](https://vercel.com/blog/vercel-security-review)

## GitHub — 에이전트 스킬의 의존성도 업데이트 PR로 받는다

Dependabot이 11월 3일부터 Agent Package Manager(APM)의 버전 업데이트를 지원합니다. `apm.yml`에 선언한 지원 대상 Git 의존성을 새 버전으로 바꾸는 PR을 열고, 잠금 파일이 있으면 함께 갱신합니다. GitHub.com의 모든 요금제에서 사용할 수 있습니다. **보안 업데이트 알림이 아니라 버전 업데이트 기능**이며, 저장소의 모든 스킬 파일을 자동 검증한다는 뜻도 아닙니다. [GitHub 변경 기록](https://github.blog/changelog/2026-11-03-dependabot-version-updates-support-agent-package-manager/)

코드 라이브러리의 버전이 바뀌면 테스트를 돌리듯, 스킬이나 지시문의 의존성이 바뀌었을 때도 에이전트가 같은 일을 어떻게 수행하는지 확인할 필요가 있습니다. PR이 생겼다는 사실은 변경을 검토할 자리를 마련해주지만, 그 변경이 원하는 행동을 유지하는지는 따로 살펴야 합니다.

## Kimi — 예고했던 K3.1 Pro 가중치가 공개됐다

11호에서 Kimi K3.1 Pro의 API 이용과 가중치 공개 예고를 구분해 소개했습니다. 11월 5일 오전 확인한 Moonshot AI의 공식 Hugging Face 저장소에는 이제 모델 카드와 가중치 파일 96개가 올라와 있습니다. 저장소에 표시된 전체 크기는 약 1.56TB이며 별도의 Kimi K3.1 Pro 라이선스가 적용됩니다. [모델 저장소](https://huggingface.co/moonshotai/Kimi-K3.1-Pro/tree/main) · [라이선스](https://huggingface.co/moonshotai/Kimi-K3.1-Pro/blob/main/LICENSE)

API에서 시험하는 것과 자체 장비에 내려받아 운영하는 것이 실제로 다른 선택지가 됐습니다. 다만 파일을 받을 수 있다는 사실만으로 작은 개발 환경에서 곧바로 실행할 수 있다는 뜻은 아닙니다. 필요한 장비와 배포 방법, 사용 조건을 따로 검토해야 합니다.

## L-Proof의 해석

### 변경을 빨리 넘기는 일과 받아들여도 되는지는 다르다

Pando는 여러 에이전트가 만든 변경을 저장소가 감당하도록 푸시와 가져오기의 병목을 줄입니다. Pierre의 도구는 사람이 그 변경을 읽는 화면을 다룹니다. Vercel은 푸시된 코드에서 보안 문제를 찾고, Dependabot은 에이전트 스킬의 의존성 변경을 PR로 올립니다. 네 소식이 해결하는 단계는 서로 다릅니다. 변경이 빨리 도착해도, 그것을 받아들일 근거가 자동으로 늘어나는 것은 아닙니다.

L-Proof가 특히 살펴볼 것은 **검토 대상의 변화**입니다. 함수 한 줄을 고친 PR은 해당 입력과 결과를 시험할 수 있습니다. 반면 스킬의 의존성을 바꾼 PR은 이후 에이전트가 어떤 도구를 부르고 어디서 멈추는지까지 바꿀 수 있습니다. 이 경우 파일 차이만 읽는 검토에 더해, 대표 작업 몇 개를 새 버전으로 다시 실행하고 행동 기록을 비교하는 편이 도움이 될 수 있습니다. 모든 스킬 업데이트에 긴 재시험을 요구하면 유지 비용이 커지므로, 권한이나 외부 전송을 다루는 작업부터 우선순위를 정하는 방식이 현실적입니다.

보안 검토 도구가 찾은 문제는 수정의 출발점이 됩니다. 문제를 찾지 못한 변경도 배포 전 확인할 것은 남습니다. 앞으로 더 보고 싶은 지표는 에이전트가 연 PR의 수보다, **어떤 종류의 변경을 어떤 근거로 통과시켰는지**입니다. 코드와 스킬이 함께 바뀌는 저장소에서 이 기록을 사람이 얼마나 짧게 검토할 수 있을까요.

## 편집자 메모 — 발행 본문 제외

- 14호 v1-private. 사용자 요청은 원고 작성까지다. 등록·최종 승인·예약·발행·발송은 실행하지 않았다.
- 조사 범위 2026-10-31~11-05 KST, 확인 마감 11-05 08:24 KST. 날짜만 표기된 원문에 임의의 KST 발표 시각을 붙이지 않았다.
- 대기 구독자 수는 이번에 확인하지 못했다. 로그인된 Cloudflare 대시보드 세션이 만료되어 로그인 화면으로 이동했다. 11월 1일의 대기 1명 기록을 현재 수치로 재사용하지 않는다.
- 13호의 GitHub Agentic Workflows, Vercel Virtual Models·CI, OpenAI의 웹사이트 학습 선호와 이번 소식은 별개의 사건이다. 12호의 AI Scan·Vercel 권한 설계·AI Traffic도 재발행하지 않았다.
