# 에이전트가 보여준 선택, 실제로 실행된 일

가령 에이전트에게 예약 후보를 물었을 때 긴 설명 대신 날짜를 고르는 카드가 나타난다면, 선택을 바꾸고 확인하는 대화는 훨씬 짧아집니다. Google이 11월 11일 공개한 A2UI 1.0은 에이전트가 이런 화면을 구조화해 설명하고, 앱이 자신의 컴포넌트로 그리도록 하는 규약입니다. [Google 발표](https://developers.googleblog.com/a2ui-10-build-delightful-fast-reliable-agentic-experiences/)

16호는 11월 7~12일 KST에 나온 에이전트 UI, 모델 접근 조건, 개발 워크플로 보안 소식을 골랐습니다. 자료 확인 마감은 11월 12일 17:22 KST입니다. 아래 소식은 모두 **03 · 공식 확인**입니다. 발표 주체의 원문으로 사실을 확인했으며 제품 동작이나 성능을 독립적으로 재현하지는 않았습니다. 마지막 ‘L-Proof의 해석’은 그 사실을 바탕으로 한 별도의 판단입니다.

## Google — 에이전트가 만든 화면을 앱의 컴포넌트로 그린다

A2UI 1.0은 생성형 UI를 위한 공개 프로토콜의 첫 안정 버전입니다. 에이전트가 화면에 놓을 요소와 데이터를 메시지로 설명하면 앱은 미리 등록한 컴포넌트로 이를 렌더링합니다. 모델이 임의의 프런트엔드 코드를 실행하는 방식과는 다릅니다. 이번 버전에는 화면에서 다시 에이전트나 서비스로 값을 보내는 양방향 함수 호출, 접근성 지원, 확장용 메타데이터가 추가됐습니다. 예를 들어 예약 후보 카드가 표시된 자리에서 가용 여부를 다시 조회할 수 있습니다. [A2UI 1.0 발표](https://developers.googleblog.com/a2ui-10-build-delightful-fast-reliable-agentic-experiences/)

웹에는 React·Angular·Lit, 여러 플랫폼에는 Flutter, iOS에는 SwiftUI 렌더러가 제시됐습니다. 다만 Android의 Jetpack Compose 렌더러는 현재 **0.9.1**을 지원하며 1.0 대응은 예정 단계입니다. Google은 A2UI가 화면을 기술하고 그리는 틀이라고 설명합니다. 실제 예약 서비스 연결과 어떤 동작을 최종 승인받을지는 이를 쓰는 앱이 구현해야 합니다. [플랫폼별 지원 범위](https://developers.googleblog.com/a2ui-10-build-delightful-fast-reliable-agentic-experiences/)

## Anthropic — 같은 기반 모델도 허용되는 작업은 다르다

Anthropic은 11월 9일 Claude Fable 5.2와 Mythos 5.2를 발표했습니다. 두 이름은 같은 기반 모델을 가리키지만 사용 조건이 다릅니다. Fable 5.2는 일반 개발자가 Claude Platform에서 `claude-fable-5-2`로 사용할 수 있고, Mythos 5.2는 사이버보안이나 생명과학 분야의 검증 프로그램을 통해 접근을 신청하는 방식입니다. [Anthropic 발표](https://www.anthropic.com/claude-fable-and-mythos-5-2)

Fable에는 고위험 사이버 활동과 생물학 연구의 상당수 작업을 막는 분류기가 적용됩니다. 해당 요청이 막히면 Anthropic은 분야에 따라 이전 Claude 모델의 응답으로 대체한다고 설명합니다. 따라서 같은 기반 모델이라는 설명만으로 두 제품의 허용 작업이나 실제 응답 경로가 같다고 볼 수 없습니다. 정상적인 업무 요청이 어디까지 차단되거나 대체되는지는 실제 사용 기록으로 확인해야 합니다. [보호 장치와 이용 조건](https://www.anthropic.com/claude-fable-and-mythos-5-2)

## GitHub — Actions 로그에서 비밀 값을 찾지만, 지나간 실행부터 본다

GitHub는 11월 9일 Secret scanning의 검사 범위를 Actions 워크플로 로그로 넓히는 공개 미리보기를 발표했습니다. 기능을 켠 뒤 **완료된 실행의 로그**에서 지원하는 제공자 비밀 값 패턴을 찾고, 발견하면 저장소의 보안 알림 목록에 해당 로그 링크를 남깁니다. 로그가 삭제돼도 알림은 남습니다. [GitHub 변경 기록](https://github.blog/changelog/2026-11-09-secret-scanning-detects-secrets-in-github-actions-workflow-logs/)

이 기능은 GitHub Enterprise Cloud에서 GitHub Secret Protection 또는 Advanced Security를 쓰는 기업을 대상으로 하며, 기본값은 꺼짐입니다. 활성화 전 실행은 소급 검사하지 않습니다. 일반 패턴·사용자 정의 패턴·AI 탐지 비밀 값과 Actions가 이미 마스킹한 값은 이 미리보기의 탐지 대상이 아닙니다. 알림 통지도 보내지 않으므로 운영자가 보안 알림 목록을 직접 확인해야 합니다. 로그에 비밀 값이 찍히지 않도록 막는 조치와, 실행이 끝난 뒤 남은 흔적을 찾는 조치는 서로 다른 단계입니다. [미리보기의 범위와 제한](https://github.blog/changelog/2026-11-09-secret-scanning-detects-secrets-in-github-actions-workflow-logs/)

## L-Proof의 해석

### 확인 버튼이 보인다고 승인 경로가 완성되지는 않는다

A2UI는 사람이 선택지를 읽고 고치기 쉬운 화면을 만들 수 있게 합니다. 그러나 카드에 표시된 선택과 서버가 실제로 받은 요청을 같은 것으로 묶는 일은 앱의 책임입니다. 예를 들어 사용자가 화면에서 월요일 오전 일정을 골랐더라도, 확인 직전에 예약 가능 시간이 바뀌었다면 앱은 새 상태와 실행할 값을 다시 보여줘야 합니다. 이것은 Google 제품에서 확인된 오류가 아니라, 동적인 화면을 실제 동작에 연결할 때 L-Proof가 확인하고 싶은 경계입니다.

Anthropic의 작업별 모델 보호 장치는 모델이 어떤 요청을 처리할지 가릅니다. GitHub의 새 검사는 워크플로가 끝난 뒤 일부 비밀 값의 흔적을 찾습니다. 둘 다 유용하지만, 사용자가 승인한 값 그대로 외부 동작이 실행됐다는 증거는 아닙니다. 반대로 GitHub에서 알림이 없다는 사실도 모든 비밀 값이 로그에 없었다는 뜻은 아닙니다. 탐지 범위와 통지 방식에 명시된 빈칸이 있기 때문입니다.

에이전트 UI를 실제 서비스에 붙일 때 L-Proof가 보고 싶은 것은 **사용자가 본 선택, 서버에 전달된 실행 값, 실행 결과**가 한 건으로 이어진 기록입니다. 화면에서 선택하기 쉬워져도 실제 실행 값이 달라질 수 있습니다. A2UI를 채택한 앱이 그 차이를 어떻게 보여주고 사용자가 바로잡게 할지 살펴볼 필요가 있습니다.

## 팩트체크·소재 선정 기록 — 발행 본문 제외

- Google A2UI 1.0: 11월 11일 공식 개발자 블로그. 안정 버전, 양방향 함수 호출·접근성·확장, 웹·Flutter·SwiftUI 렌더러와 Jetpack Compose 0.9.1/1.0 예정의 차이를 확인했다. 프로토콜이 실제 예약이나 승인 정책을 자동 제공한다고 쓰지 않았다.
- Anthropic Claude Fable/Mythos 5.2: 11월 9일 공식 발표. 동일 기반 모델, Fable의 공개 이용, Mythos의 검증 프로그램, Fable 차단 시 이전 모델 응답 경로를 확인했다. 회사 자체 성능 수치를 검증 사실로 격상하지 않았다.
- GitHub Actions 로그 Secret scanning: 11월 9일 공식 변경 기록. 완료된 실행만 검사, 기업·라이선스·기본 비활성 조건, 소급 검사·일반/사용자 정의/AI 패턴·통지 제외를 확인했다. 예방 기능이나 모든 비밀 값의 탐지로 표현하지 않았다.
- 15호의 Google Agent Distraction, OpenAI GPT-6-Cyber, GitHub Copilot 코드 리뷰 API는 같은 발표를 재수록하지 않았다. GitHub의 Fable 5.2 및 Gemini 4 Carbon 모델 선택기 추가는 위 Anthropic 모델 발표나 단순 공급 채널 확대와 중복되어 별도 항목으로 싣지 않았다. Vercel AI Gateway의 개별 모델 추가와 GitHub C++ 언어 서버 자동 설정은 이번 세 항목보다 독립적 새 정보의 양이 적어 보류했다.
